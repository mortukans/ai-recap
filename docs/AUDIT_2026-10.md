# AI Recap — full codebase audit (2026-10)

A six-dimension audit of the shipped v1.0.1 app (security/privacy, correctness/reliability,
performance, code quality, test coverage/CI, product/UX/a11y/roadmap). This records every finding and
whether it was **fixed in v1.0.2** or **deferred** (with why).

## ✅ Fixed in v1.0.2

**Correctness / reliability** (`src/processing/coordinator.ts`, `src/ai/transcription/*`)
- **[P0] Foreground mid-recording no longer finalizes the live recording.** The AppState→active handler
  called `recover()`, which treated any `recording`-status recap as a crash orphan — so locking/returning
  mid-recording finalized it, transcribed a partial, then double-processed on Finish. `recover()` is now
  cold-launch-only; the foreground path uses `resumeResting()`, which never touches `recording` recaps.
- **[P1] Stall watchdog now aborts the pass.** It only set a failed status before; the un-aborted work
  kept running and could resurrect the status to transcribed/ready and double-write the transcript
  (`replaceSegments` delete-then-insert racing a retry). It now `controller.abort()`s first.
- **[P1] Heartbeat during the native audio split.** A long watch recording splits in one opaque native
  call; the watchdog could fire mid-split and (pre-fix) orphan it. A 60 s heartbeat keeps it armed.
- **[P1] A transient empty model reply is no longer a futile retry.** The resume cache is cleared before
  throwing the "came back empty" error, so Retry re-requests instead of reusing cached empties.
- **[P2] Resume cache cleared on `ready`** (was leaking the whole transcript into AsyncStorage for
  partially-failed recaps). **[P2] On-device transcription attributed correctly** in usage accounting
  (`SmartTranscriber` now reports the concrete provider's `runsOnDevice`).

**Performance**
- **DB indexes** added on every hot column (migration `0001`): `transcript_segments(recap_id,start_time)`,
  `audio_chunks(recap_id,index)`, `generated_artifacts`, `recap_speakers`, `chat_messages`, `attachments`
  by `recap_id`; `recaps(started_at)` + `recaps(status)`; `usage_records(occurred_at)` + `(synced…)`.
  Previously every list/search was a full table scan.
- **Home screen no longer reloads the whole library on every chunk** — the coordinator-driven reload is
  debounced (300 ms), and **search is debounced** (250 ms).

**Security / privacy**
- **Crash payloads scrubbed** (`crash-format.ts` `scrubSecrets`): API keys, bearer tokens, JWTs and
  base64 blobs are redacted from `message`/`stack` before they leave the device (defense-in-depth, since
  some error strings interpolate provider response bodies). Covered by new tests.
- Project identifiers redacted from the public `docs/BACKEND_SETUP.md`; stale `processing-audio` bucket
  instruction removed from `docs/BUILD.md` (the hosted functions send audio inline, never to a bucket).

**Code quality / infra**
- **CI gate added** (`.github/workflows/ci.yml`): typecheck + tests on every push/PR (lint non-blocking
  for now). Previously nothing ran checks before a release build.
- Real lint anti-patterns fixed where touched: `Plan` hoisted out of render in `paywall.tsx`,
  `Date.now()` memoized in the home header.

**Accessibility / UX**
- VoiceOver labels + roles on the **home list rows** (with an accessible *delete* action, not just
  long-press), the **paywall** buy/restore/plan controls (+ `accessibilityState`), and the **chat send**
  button. Dead chevrons removed from the read-only Settings → Recording rows.

## ✅ Resolved after review
- **OpenAI/Whisper BYOK path removed** (the privacy-disclosure + reliability finding). The direct
  `api.openai.com` transcriber (`openaiWhisper.ts`), its SmartTranscriber branch, the Settings key UI,
  and the `getOpenAiKey`/`setOpenAiKey` store were deleted. BYOK audio now only ever goes to OpenRouter
  (Whisper and other STT models remain selectable **through** OpenRouter), so the data flow matches the
  live privacy policy's "only OpenRouter" statement — no policy change needed.

## Deferred (with reason) — roadmap, biggest value first
- **Transcript virtualization** (perf P1, the single worst perf issue): the transcript renders every
  segment in a ScrollView. Fixing it well needs variable-height `scrollToIndex` for the follow-playback
  behavior — its own build + on-device test.
- **Expo patch bumps** (9 packages one patch behind): the supported `expo install --fix` conflicts with
  the workspace `overrides.expo` pin; needs a deliberate bump of the override + lockfile + a native
  build test (incl. expo-widgets, which powers the Island). Not a bug fix, so held back.
- **App Store ratings prompt** (growth, high ROI): `expo-store-review` after a 2nd–3rd successful recap.
- **Finish + ship the watch-face complication** (`feat/watch-complication`, blocker already resolved).
- **Server-side background processing** for Unlimited (true unattended completion of long recordings).
- **Product analytics** (none today — blind on activation/paywall conversion/failure rates).
- **`log-error` hardening**: unauthenticated + no server-side rate limit (Edge Function change + deploy).
- **Transcription test coverage**: `openrouterAudio`/`openrouterStt` orchestration, `parseTranscript`
  (extract to an RN-free module first), `normalizeChunks` — the most incident-prone, least-tested code.
- **Lint → fully green** + delete the dead Expo-template component cluster + duplicate `useTheme`.
- **Dedupe the two OpenRouter transcribers'** shared resilient chunk-loop.
- **Dynamic Type / contrast / touch-target** polish; port the 3 legacy-styled screens (paywall,
  onboarding, chat) to the design system.
- Minor: watch manifest de-dupe by index; `timeoutSignal` timer cleanup; `requireFairUse` fail-closed.

## Verified clean (no action)
No committed secrets; Supabase RLS is sound (every table `auth.uid()`-scoped, service-role-only for
entitlements/quota/errors); hosted AI path persists no content; deep links do nothing destructive;
BYOK keys live in the Keychain and are sent only to the provider. Type safety is strong (no `any` in
prod); no stray `console.log`/TODO/empty-catch. Reduce-motion support is thorough; i18n LV/EN parity is
compile-enforced.
